## Ошибки

### Откуда берутся ошибки

- **Ошибки выполнения** — деление на ноль, неизвестное имя, неверный тип, индекс вне диапазона, вызов не-функции, изменение неизменяемой переменной и т. д.
- **Явные**: `бросить значение` и встроенная `ошибка("текст")`.
- **Ошибки разбора** (синтаксис) обнаруживаются до запуска, программа не стартует.

Необработанная ошибка завершает программу с кодом **1** и печатает:

```
❌ ОШИБКА [файл.молитва:3] индекс 9 вне пределов стана (в массиве всего 2)
📖 Наставление: Дозволенные индексы: от 0 до 1. Счёт ведётся с нуля.
📚 Стек вызовов (от свежего к старому):
   1. г — файл.молитва:2
   2. б — файл.молитва:1
   3. а — файл.молитва:4
```

Номер строки и колонка, наставление (`📖`) и стек вызовов добавляются автоматически.

### `попытка … поймать … всегда`

```
попытка
    пусть x = 1 / 0
поймать e
    возгласи("поймано: ", e)       # поймано: деление на ноль
всегда
    возгласи("выполнится в любом случае")
конец
```

- Блоки `поймать` и `всегда` необязательны. Без `поймать` ошибка после выполнения `всегда` продолжает лететь наружу.
- Имя после `поймать` — переменная с пойманной ошибкой; она видна только внутри блока `поймать`. Имя можно опустить (`поймать` без имени), если сама ошибка не нужна.
- Блок `всегда` выполняется **всегда**: после успешного тела, после `поймать`, а также при `аминь`, `прерви`, `продолжи` внутри `попытка`.

```
слово спас()
    попытка
        аминь 1
    всегда
        возгласи("финал")       # выведется до возврата
    конец
конец
спас()      # печатает «финал», возвращает 1
```

- `попытка` можно вкладывать; из `поймать` можно снова `бросить`:

```
попытка
    попытка
        бросить "внутр"
    поймать e
        бросить "внешн из " + e
    конец
поймать e2
    возгласи(e2)               # внешн из внутр
конец
```

### Что такое пойманное значение

Пойманное `e` — значение типа `ERROR_VALUE`. Оно ведёт себя как «сообщение»:

- печатается как текст сообщения (для `бросить "т"` — `т`; для `бросить {…}` — как словарь);
- сравнивается и складывается со строками: `e == "т"`, `e + "!"`;
- `строка(e)` возвращает сообщение;
- полей и методов у него нет (`e.код` — ошибка). Если нужны структурированные ошибки, бросайте строки с договорённым форматом, например `"НЕТ_ФАЙЛА: данные.txt"`, и разбирайте через `начинается_с`/`разделить`.

### `бросить` и `ошибка`

```
бросить "что-то пошло не так"
бросить {"код": 404, "текст": "нет"}      # допустимо любое значение
```

Отличие `ошибка("текст")`: это встроенное слово, которое немедленно создаёт **ошибку выполнения** с подсказкой «создана явно функцией ошибка()» и номером строки. Внутри `попытка` она ловится так же, как `бросить`; вне `попытка` — прерывает программу. Используйте `бросить` для собственных ошибок, `ошибка` — когда нужна стандартная ошибка с трассировкой.

### Ошибки в особых контекстах

- **Генераторы**: ошибка в теле генератора досрочно **завершает** генерацию; потребитель (`для`, `взять`) просто получает меньше значений, исключение наружу не всплывает. Проверяйте входные данные до `выдать`.
- **`асинх`**: ошибка всплывает в точке `ждать`.
- **Конструктор образа**: ошибка прерывает создание объекта.
- **`тест`**: ошибка внутри теста не прерывает программу — тест помечается как проваленный (см. ниже).

### Типичные ловушки

- `в`, `и`, `или`, `не`, `от`, `до`, `по`, `из`, `как`, `это` — ключевые слова: нельзя назвать так переменную или параметр (`пусть в = 1` — ошибка разбора).
- `аминь` без значения не допускается: пишите `аминь ничего`.
- Литералы `1e3` и `0x10` не поддерживаются.

## Тесты

Тесты — часть языка:

```
слово сложить(а, б): а + б

тест "сложение"
    проверить сложить(2, 3) == 5
    проверить сложить(-1, 1) == 0
конец

тест "текст"
    проверить "привет".верхний() == "ПРИВЕТ"
конец
```

Запуск — обычным способом `zavet файл.молитва`; тесты выполняются на месте, где записаны:

```
  ✓ сложение
  ✓ текст
```

Проваленный тест:

```
  ✗ сложение
    ❌ ОШИБКА [файл.молитва:3] испытание не пройдено
```

Правила:

- `тест "название" … конец` — блок; внутри можно всё (переменные, циклы, `попытка`).
- `проверить выражение` — ложь (`ложь`) или `ничего` проваливает тест; любое другое значение считается успехом (в том числе `0` и `""`, как и везде в Завете).
- После первой проваленной проверки остаток теста **не выполняется**; другие тесты продолжают выполняться.
- Любая необработанная ошибка в тесте (индекс, деление на ноль, `бросить`) также помечает его проваленным.
- Вне блока `тест` `проверить` с ложным условием останавливает программу обычной ошибкой.
- Сообщения-пояснения к `проверить` не поддерживаются (`проверить a, "текст"` — ошибка разбора).
- Код выхода программы с проваленными тестами — 0: для CI смотрите вывод (`✗`) или используйте собственный `выход(1)` в конце файла.
- Не путайте с командой `zavet проверить` — это линтер (см. [главу 06](06_ИНСТРУМЕНТЫ.md)).

Тесты самого языка — golden-файлы в `tests/cases/*.молитва` с эталоном `*.expected`; запускаются командой `go test ./...`.

## Модули

Модуль — обычный файл `.молитва`. Он **выполняется целиком** при импорте, а наружу отдаёт только то, что помечено `открой`.

### Экспорт: `открой`

`открой` ставится перед определением:

```
# файл геометрия.молитва
открой пусть ПИ = 3.14159

открой слово площадь_круга(r)
    аминь ПИ * r * r
конец

открой образ Прямоугольник
    слово создать(a, b)
        это.a = a
        это.b = b
    конец
    слово площадь(): это.a * это.b
конец

открой род Фигура
    круг
    квадрат
конец

слово скрытое(): "не видно снаружи"      # без открой — приватно
```

Что можно экспортировать: `пусть`-константы, слова, образы, роды. Особенности:

- Экспортируется **значение на момент объявления**. Изменяемая переменная (`измени`) не экспортируется — её нужно отдавать через слова-аксессоры:

```
измени счёт = 0
открой слово нарастить()
    счёт += 1
    аминь счёт
конец
```

- Модуль без `открой` отдаёт пустой словарь.

### Импорт: `приими … из … как`

```
приими геометрия из "геометрия.молитва"
возгласи(геометрия.площадь_круга(2))
возгласи(геометрия.Прямоугольник(3, 4).площадь())
возгласи(геометрия.Фигура.круг)

приими г из "./геометрия.молитва" как гео     # псевдоним
возгласи(гео.ПИ)
```

- Форма: `приими ИМЯ из "путь" [как АЛИАС]`. Модуль привязывается к имени `АЛИАС` (если задан), иначе `ИМЯ`. Результат — **словарь** экспортов (`ключи(геометрия)` показывает их).
- Обращение — через точку, вызов слов — `модуль.слово(…)`.
- Импорт распаковки отдельных имён (`приими {a, b} из …`) не поддерживается: берите из словаря или присваивайте `пусть площадь = геометрия.площадь_круга`.
- Модуль выполняется **при каждом** `приими` (кэша нет); не импортируйте один и тот же модуль повторно без необходимости.
- Экспортированные слова остаются замкнутыми на окружение модуля: приватные переменные и слова модуля им доступны.
- Ошибка внутри модуля прерывает импорт и всплывает в месте `приими`.
- Модуль «видит» глобальные имена импортирующего файла (его окружение — родительское). Не опирайтесь на это.

### Как ищется файл

| Путь в строке | Откуда берётся |
|---------------|----------------|
| абсолютный | как есть |
| начинается с `./`, `../` или оканчивается на `.молитва` | относительно **файла, в котором написан `приими`** (а не рабочей папки) |
| иначе (`"матем"`) | **пакет**: `пакеты/матем/` в корне проекта (см. ниже) |
| имя стандартного модуля (`"json"`, `"окно"` …) | встроенный модуль, файла не нужно |

### Стандартные модули

Они доступны и без импорта по своему имени (`json.разобрать(…)`), а `приими` нужен лишь для явности:

```
приими json из "json"
приими файлы из "файлы"
```

Полный перечень — в [СТДЛИБ.md](СТДЛИБ.md). Модуль `окно` — в [ОКНО.md](ОКНО.md).

### `загрузить`

Встроенное `загрузить("файл.молитва")` читает файл и выполняет его **в текущем окружении** (всё определённое в файле попадает прямо в ваши имена, без словаря и без `открой`). Это «include», а не модуль; для библиотек предпочитайте `приими`. В безопасном режиме запрещено.

## Пакеты

Пакет — папка с `пакет.json` и исходниками. Зависимости ставятся через `git` в папку `пакеты/`.

### Манифест `пакет.json`

```json
{
  "имя": "мой_проект",
  "версия": "0.1.0",
  "описание": "Что делает проект",
  "автор": "Имя",
  "лицензия": "MIT",
  "точка_входа": "главный.молитва",
  "зависимости": {
    "матем": "github.com/автор/матем@v1.0.0"
  }
}
```

Обязательны `имя` и `версия`; остальные поля необязательны. Точка входа по умолчанию — `главный.молитва`.

### Команды

| Команда | Действие |
|---------|----------|
| `zavet инит [имя]` | создаёт `пакет.json` и `главный.молитва` |
| `zavet подключить ИМЯ` | ставит пакет по **короткому имени** из реестра `zavet-registry` (или встроенного каталога) |
| `zavet подключить github.com/у/п[@версия]` | ставит по URL; `@версия` — тег, ветка или SHA коммита |
| `zavet подключить` | ставит все зависимости из манифеста |
| `zavet удалить ИМЯ` | удаляет пакет и запись в манифесте |
| `zavet список` | показывает установленные пакеты |
| `zavet запустить [файл]` | запускает `точка_входа` (или указанный файл) |

Нужен установленный `git` и доступ к сети. Точные версии (коммиты) записываются в `пакет.lock` (JSON: имя, источник, версия, коммит) — коммитьте этот файл, чтобы сборки были воспроизводимыми.

### Использование

```
приими матем из "матем"
возгласи(матем.факториал(5))
```

Для `"матем"` ищется `пакеты/матем/`: берётся `точка_входа` из его `пакет.json`, иначе `главный.молитва`, иначе `матем.молитва`. Корень проекта — ближайшая вверх по дереву папка с `пакет.json`. Если пакета нет, ошибка подскажет: «Установите его командой: `zavet подключить матем`».

### Выпуск собственного пакета

1. `zavet инит имя`, заполните описание, лицензию.
2. Экспортируйте публичный API через `открой`.
3. Положите репозиторий на GitHub, поставьте тег (`git tag v1.0.0`).
4. Пользователи ставят: `zavet подключить github.com/вы/имя@v1.0.0`.
