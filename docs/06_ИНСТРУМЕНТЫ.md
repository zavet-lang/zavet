## Командная строка

```
zavet <файл.молитва>               запустить файл
zavet запустить [файл]             запустить точку входа из пакет.json (или файл)
zavet инит [имя]                   создать пакет.json и главный.молитва
zavet подключить ИМЯ|URL[@версия]  установить пакет (без аргумента — все из манифеста)
zavet удалить ИМЯ                  удалить пакет
zavet список                       показать зависимости
zavet реестр [запрос]              поиск пакетов в реестре (проверенные пакеты + онлайн)
zavet формат [-в] файл|папка|-     отформатировать
zavet проверить файл|папка         линтер
zavet док файл|папка [-o файл.md]  автогенерация Markdown-документации API
zavet отладка файл.молитва         пошаговый интерактивный отладчик
zavet lsp                          сервер языка (stdio)
zavet mcp                          MCP-сервер (stdio)
zavet помощь | --help | -h         справка
zavet версия | --version | -v      версия
zavet                              REPL
```

Глобальные флаги распознаются **в любом месте** командной строки и скрипту не передаются (поэтому скрипт не увидит собственные флаги с такими именами):

| Флаг | Действие |
|------|----------|
| `--безопасный` / `--safe` | [песочница](07_ОСОБЕННОСТИ.md#безопасный-режим) |
| `--разрешить-хост=хост` / `--allow-host=хост` | разрешённый хост для исходящего HTTP (только вместе с `--безопасный`); можно указывать несколько раз |
| `--vm` | исполнение на [байткод-VM](07_ОСОБЕННОСТИ.md#байткод-vm) |

Пакетные команды описаны в [главе 04](04_ОШИБКИ_ТЕСТЫ_МОДУЛИ.md#пакеты).

## Запуск программ

```
zavet программа.молитва
zavet --безопасный программа.молитва
zavet программа.молитва --имя=Аня файл.txt     # аргументы скрипту (см. модуль cli)
```

- Файл читается в UTF-8 (BOM допускается).
- Сначала весь файл разбирается: при синтаксических ошибках выводится список `❌ Ошибки парсинга` со строками, и программа не запускается.
- Затем выполняется. Необработанная ошибка печатается с файлом, строкой, подсказкой и стеком вызовов; код выхода **1**.
- Код выхода по умолчанию 0. Явно: `ос.выход(код)`.
- Результат последнего выражения верхнего уровня программой не печатается (в отличие от REPL).
- `zavet запустить` без файла берёт `точка_входа` из `пакет.json` (по умолчанию `главный.молитва`).

## REPL

`zavet` без аргументов запускает интерактивный режим с приглашением `>>>`:

```
>>> пусть а = 5
>>> а * 2
10
>>> слово кв(x): x * x
слово(...)
>>> кв(7)
49
>>> выход
```

- **Одна строка — одна инструкция**: многострочные блоки (`если … конец`) в REPL не вводятся; используйте однострочные формы (`слово f(x): x * 2`, `если …: … иначе: …`).
- Окружение сохраняется между строками.
- Значение выражения печатается (кроме `ничего`); определение слова печатает `слово(...)`.
- Ошибка выполнения печатается, сессия продолжается.
- Выход: `выход` или `exit`, либо конец ввода (Ctrl+Z, Enter на Windows; Ctrl+D на Linux/macOS).

## Форматтер `формат`

Приводит исходник к единому стилю (канон описан в [СТИЛЬ.md](../СТИЛЬ.md)): отступ 4 пробела, пробелы вокруг операторов и после запятых, `конец` на уровне открывающей конструкции.

```
zavet формат файл.молитва          # результат в stdout
zavet формат -в файл.молитва       # переписать файл (-w — то же)
zavet формат -в папка              # все .молитва в папке рекурсивно
echo "пусть  а=1" | zavet формат - # из stdin в stdout
```

До:

```
слово ф(а,б)
пусть х=а+б
если х>3
возгласи("много")
иначе
возгласи("мало")
конец
аминь х
конец
```

После:

```
слово ф(а, б)
    пусть х = а + б
    если х > 3
        возгласи("много")
    иначе
        возгласи("мало")
    конец
    аминь х
конец
```

Свойства:

- форматирование **идемпотентно**: повторный запуск ничего не меняет;
- смысл программы не меняется (форматтер работает по дереву разбора; файл с синтаксической ошибкой не форматируется — выводится список ошибок);
- комментарии `#` сохраняются, но **концевой** комментарий (`пусть а = 1  # хвост`) переносится отдельной строкой над инструкцией;
- команды `тест`/`проверить` выводятся в исходной форме.

## Линтер `проверить`

```
zavet проверить файл.молитва
zavet проверить .            # рекурсивно, кроме папок пакеты/, .git, node_modules
```

Вывод — по строке на проблему: `⚠`/`✗`, файл:строка, `[код]`, пояснение; в конце `Найдено проблем: N`. Если проблем нет — `✓ Проблем не найдено`. Код выхода 1, если проблемы найдены.

| Код | Уровень | Что ловит |
|-----|---------|-----------|
| `parse-error` | ✗ | синтаксическая ошибка |
| `const-reassign` | ✗ | присваивание переменной, объявленной через `пусть` |
| `unused-var` | ⚠ | переменная/константа объявлена, но не используется |
| `unused-func` | ⚠ | слово объявлено, но не вызывается (экспортируемые `открой` и `создать` исключены) |
| `shadow` | ⚠ | имя во вложенной области затеняет внешнее |
| `unreachable` | ⚠ | код после `аминь`, `бросить`, `прерви` |
| `empty-block` | ⚠ | пустое тело `если` или `для` |

Примеры:

```
пусть неиспользуемая = 1               # unused-var
слово ф()
    аминь 1
    возгласи("недостижимо")            # unreachable
конец
```

Не путайте команду `проверить` (линтер) с оператором языка `проверить` внутри `тест` (см. [главу 04](04_ОШИБКИ_ТЕСТЫ_МОДУЛИ.md#тесты)).

## Редакторы и LSP

### Расширение для VS Code / Cursor

Каталог `vscode-extension/`: подсветка синтаксиса, сниппеты, иконка файлов `.молитва`. Сборка — стандартная (`npm install`, `vsce package`); готовый пакет — `zavet-lang-0.1.0.vsix`. Установка: «Extensions → … → Install from VSIX».

### Сервер языка

`zavet lsp` — LSP по stdio. Возможности:

| Функция | Описание |
|---------|----------|
| Диагностика | синтаксические ошибки и предупреждения линтера при вводе |
| Автодополнение | ключевые слова, встроенные слова, имена из файла, члены модулей |
| Подсказка при наведении | сигнатура/описание |
| Переход к определению, поиск ссылок, переименование | по файлу |
| Структура документа | слова, образы, переменные |
| Подсказка параметров | при вводе `(` и `,` |
| Форматирование | как `zavet формат` |

Подключите команду `zavet lsp` в любом LSP-клиенте (Neovim, Helix, Zed, расширение VS Code с универсальным клиентом) для языка `.молитва`.

## MCP-сервер для ИИ-агентов

`zavet mcp` — сервер Model Context Protocol (stdio). Агент (например, в Cursor) получает инструменты:

| Инструмент | Что делает |
|------------|------------|
| `run` | запускает код Завета |
| `format` | форматирует код |
| `lint` | прогоняет линтер |
| `syntax_check` | проверяет синтаксис |
| `list_modules`, `module_info` | перечень и описание стандартных модулей |
| `search_packages` | поиск пакетов в реестре |
| `language_reference` | краткая справка по языку |

Подключение в `mcp.json` клиента:

```json
{
  "mcpServers": {
    "zavet": { "command": "zavet", "args": ["mcp"] }
  }
}
```

> Справка `language_reference` — краткая; полным источником истины является эта документация.

## Реестр пакетов `реестр`

```
zavet реестр                 # показать все пакеты каталога (встроенные + онлайн)
zavet реестр тг              # поиск по имени, категории или описанию
```

Каталог проверенных пакетов (`валидатор`, `дата`, `тг`, `цвета`) встроен в бинарник (работает даже без сети) и при наличии интернета объединяется с онлайн-реестром (`registry/registry.json`).

## Генератор документации `док`

```
zavet док файл.молитва                    # Markdown в stdout
zavet док src/ -o API.md                  # вся папка в файл
zavet док src/ --только-экспорт -o API.md # только объявления с открой
```

Извлекает `#`-комментарии непосредственно перед объявлениями (`слово`, `образ`, `род`, `пусть`), сохраняет параметры, значения по умолчанию, опциональные типы (`: Тип`, `-> Тип`) и методы образов.

## Отладчик `отладка`

```
zavet отладка программа.молитва
```

Пошаговый интерактивный отладчик:

| Команда | Сокращение | Действие |
|---------|------------|----------|
| `шаг` | `s` | шаг с заходом в слово |
| `далее` | `n` / Enter | шаг без захода |
| `выйти` | `o` | выйти из текущего слова |
| `продолжить` | `c` | идти до следующей точки останова |
| `точка N` / `убрать N` / `точки` | `b N` / `d N` / `bl` | управление точками останова |
| `переменные` | `v` | локальные переменные текущего кадра |
| `вычислить <выр>` | `p <выр>` | вычислить выражение в текущем окружении |
| `стек` | `bt` | стек вызовов |
| `код` | `l` | показать строки исходника вокруг текущей |
| `выход` | `q` | прервать отладку |

## Тесты проекта и сборка

Для разработчиков самого интерпретатора (Go ≥ 1.26):

```
go build -ldflags "-X main.Version=1.1.0" -o zavet .   # сборка
go test ./...                                          # все тесты
go test ./tests -v                                     # golden-тесты языка
```

- `tests/cases/NN_имя.молитва` + `NN_имя.expected` — вход и точный ожидаемый вывод; каждая новая возможность языка должна получить такой случай.
- Примеры `examples/*.молитва` прогоняются тестами как дымовые.
- `make build`, `make test`, `make run-examples` — обёртки над теми же командами.
- Релизы: `.goreleaser.yml` собирает `zavet` для Windows (amd64), Linux и macOS (amd64, arm64) без CGO; в архивы кладётся бинарник. Версия вшивается флагом `-X main.Version`.
- Сборка для браузера (WASM): `wasm-main.go` (тег `js && wasm`) — интерпретатор для онлайн-песочницы.
